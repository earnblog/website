# 视频口播稿模式

财经视频的口播稿。选题、框架、核数字、政治过滤、免责声明都按 SKILL.md 和 style-rules.md;整篇结构按 `architecture.md`(问题链、概念阶梯、引研究要准、推导数字标明假设、缺陷段)。这里只写视频和文章不一样的地方。

结构参照 2026-11-02 拆过的一期 16 分钟财经视频(一个狠人《共识说崩就崩》),只学结构,不学内容。

## 篇幅

- **长版**:8-16 分钟,只讲一个核心命题。
- **短版**:60 秒以内,只讲问题链里最反直觉的那一问。
- 字数按**每分钟约 300 字**估(正常语速)。参照视频语速约每分钟 400 字,偏快,不要照抄。12 分钟的长版约 3600 字。

## 标题

- 把**核心结论 + 3-5 个钩子**塞进标题:反常数字、反直觉短语、具体的动作("吃做市商那一跳")。没点开的人也该知道这期讲什么。
- YouTube 标题上限 100 字符,超了先砍最弱的钩子。
- 不用感叹号也可以;视频标题靠钩子密度,不靠语气。

## 时间轴结构(以 12 分钟长版为例)

| 时段 | 内容 | 要点 |
|---|---|---|
| 0:00-0:30 | **反常数字钩子** | 一个和直觉反着、核实过的数字,外加一句"这就是今天要讲的"。前 30 秒决定观众留不留 |
| 0:30-1:00 | **系列回顾**(系列第二期起) | 前几期各压成一句话,然后说今天是第几件事。第一期跳过 |
| 1:00-1:20 | **结论前置** | 直接说核心命题,接路标句:"后面讲的全是在解释这句话" |
| 1:20-9:00 | **问题链主体** | 4-6 个问题段,每段 1.5-2 分钟。每段:生活例子起步 → 机制 → 一个现实案例 → 段尾抛下一个问题 |
| 9:00-10:30 | **落地** | 观众可以自己做的观察方法,不给买卖建议 |
| 10:30-11:15 | **缺陷段** | 这个方法什么时候会失效。主动说出来 |
| 11:15-12:00 | **收尾** | 末句金句 → 一句口播版免责声明 → 下期要回答的问题 |

## 口播语言

文章是看的,口播是听的,读者不能回看:

- **一句不超过 20 个字。** 长句拆成两三句说。
- **一句最多一个数字。** 数字写成口语读法:"5891 亿"写成"五千八百九十一亿";百分比、倍数都写成汉字读音。
- **公式口播化**:不念符号,说成"人数除以一加上人数减一再乘相关系数"。能用画面代替就用画面(style-rules「能换画面就别解释」)。
- **每 30-60 秒有一处口语调节**:"有点意思吧""这下就通了""你看"。用来让听众喘口气,不是抖机灵,别用表演性的金句栏目。
- **段尾的设问要说出来**:"那问题来了,为什么是同一秒?" 文章里是一句,口播里可以停半拍再接。
- **专业名词首次出现**:说中文名,同时在屏幕文字里打出英文原名和年份。语音转写和自动字幕会把外文人名、模型名转错(参照视频里 Ising 模型被转成"一系模型"),屏幕文字能兜底。

## 稿件格式

每段写成三栏,方便录制和剪辑:

```
【段落 3 | 约 1:50 | 问题:为什么是同一秒崩?】
口播:
  〔逐句口播稿,一行一句〕
屏幕:
  〔要打在屏幕上的字:关键数字、模型名+年份、一句结论〕
画面:
  〔建议的图:机制示意图从 diagrams.md 套路里挑,或数据图〕
```

稿件开头单列:标题、一句话核心命题、问题链(3-5 个问题)、预计总时长。结尾单列:本期用到的所有数字和来源(给自己核对用,不念)。

## 和文章模式的区别汇总

| | 文章 | 口播稿 |
|---|---|---|
| 开头 | 四选一 | 固定用反常数字钩子 |
| 句长 | 短句排比 + 四字循环 | 一句不超过 20 字,少用四字成语堆叠(听不清) |
| 数字 | 单篇 8 个以内 | 单期 10 个以内,一句最多一个 |
| 术语 | 就地换画面 | 换画面 + 屏幕文字打原名 |
| 免责声明 | 文末斜体 | 收尾口播一句 + 视频简介里写一遍 |
| 自检 | fingerprint.md ≥7 条 | fingerprint.md 第 3、7、8、13、14、15、16 条必须满足,其余不强求 |

## 硬规则

- 数字照样逐个核到一手源;核不到的数字不进稿,也不进屏幕文字。
- 架构文件里"不学的两件事"同样适用:不把假设参数算出的数当事实,不只引研究的一半。
- 不碰政治;财经视频比文章更容易被平台按政策下架,边界从严。
